# 단계별 구현 해설

로드맵의 각 단계를 하나씩 따라가며 "무엇을 왜 이렇게 만들었는지", "어떤 기술을 어디에 썼는지", "어떻게 직접 확인하는지", "면접에서 어떻게 설명하는지"를 정리한 문서입니다. 5a부터는 "사용한 기술" 절이 있습니다. 단계를 진행할 때마다 한 편씩 추가합니다.

| 단계 | 문서 | 내용 |
|---|---|---|
| 2a | [Kafka 기반](2a_kafka.md) | Kafka 브로커, 토픽, 이벤트 겉봉투, 생산자·소비자 설정 |
| 2b | [football-data.org 수집기](2b_football_data_org.md) | 요청 한도·429 처리, 경기 상황에 맞춘 조회 간격, Bronze 보존, 바뀐 경우에만 발행 |
| 2c | [Kafka 소비자 → Silver](2c_consumer.md) | 중복·늦은 도착·깨진 메시지 처리, DB 커밋 후 오프셋 커밋, Gold의 소스 우선순위 |
| 2d | [과거 시즌 재생기](2d_replay.md) | 장애(중복·늦은 도착)를 일부러 섞어 시즌 전체를 재생하고 최종 상태를 원본과 대조 |
| 2e | [경기 전 자동 스냅샷](2e_prematch_snapshots.md) | 시작 24·3·1시간 전 입력 고정, 놓친 시점은 MISSED, 사전 기록(PROSPECTIVE) 평가의 근거 |
| 3a | [시간순 학습·평가 데이터셋](3a_dataset.md) | 3단계 계획, 과거 재구성 가정(시작+3시간), 누수 없는 팀 지표, 두 겹의 누수 검사 |
| 3b | [기준 모델과 시간순 백테스트](3b_baseline_models.md) | 단순 비율·Poisson·Dixon-Coles, 주 단위 재학습, 검증·시험 시즌 분리, 축소 추정, 시장 대비 결과 |
| 3c | [평가 보고서](3c_evaluation.md) | 블록 부트스트랩 불확실성, 확률 보정, 승격 팀 과대평가·확률 눌림 발견, 검증 기준(모두 NOT_VALIDATED) |
| 3d | [경기 전 예측 기록과 주간 채점](3d_prospective_predictions.md) | 스냅샷 순간에만 예측, 실제 수신 자료로 학습, 같은 as_of를 DB가 강제, 검증 전 WITHHELD, 주간 보고서 DAG |
| 3e | [모델 개선](3e_model_improvements.md) | 승격 첫 시즌 효과, 확률 보정, 2020-21 추가, 검증 두 시즌, 실패와 판단 과정, 시험을 본 횟수 공개 |
| 3f | [교차 보정](3f_cross_fit_calibration.md) | 보정 계수를 고른 자료로 채점하는 낙관 측정·제거, 시즌 단위 교차, 고른 방법을 버전에 기록 |
| 3g | [경기 기록과 시장 결합](3g_match_stats_and_market.md) | 유효 슈팅·퇴장·휴식·시장 결합 실험(모두 효과 없음), 라인업·교체·퇴장을 쓸 수 있는지 |
| 4a | [데이터 레이크와 Spark](4a_spark_lake.md) | Gold → Parquet(lake 버킷), Spark 재계산, dbt와 2,660경기 × 18열 대조 불일치 0, CI에서 Spark 테스트 |
| 4b | [텔레그램 알림](4b_telegram_alerts.md) | 들어오는 길 없이 내보내기, 경기 전·주간·실패 알림, 중복 방지, 토큰 보호, 봇 설정 방법 |
| 5a | [다섯 리그로 확장](5a_multi_league.md) | 소스 확인, 리그 목록 한곳에, 팀 대조표 76개 검토, 수집기·DAG 확장, 모델 없는 리그는 보류 |
| 5b | [The Odds API 배당 자동 수집](5b_odds_api.md) | 이용 조건, 크레딧 예산(24·1시간 전만), 팀 대조표 96개, Pinnacle 우선 해외 기준 확률, 수동 fixtures.csv 대체 |
| 5c | [리그별 모델](5c_league_models.md) | 리그별 백테스트·평가·활성 모델, 리그마다 다른 설정·무승부·승격 팀 경향, 시장 비교 자료가 없는 리그의 검증 |
| 5d-a | [NBA 경기 수집](5d_nba_games.md) | balldontlie 약관, 축구와 다른 경기 정체성(같은 대진 반복·무승부 없음), 쪽 단위 Bronze, 분당 5회, 아홉 시즌 수집·우승팀 대조, 소스 점수 오류 2건 |
| 5d-b | [NBA 배당](5d_b_nba_odds.md) | 크레딧 예산(하루 1번), 동부 날짜로 경기 묶기, 시작 시각 10분 차이와 3시간 연결 범위, 대조표가 NBA 팀을 축구로 만들던 문제 |
| 5d-c | [NBA 모델](5d_c_nba_models.md) | 점수 차 등급·Elo·연전 효과, 버블 중립 경기, 격자 끝 선택과 시험 횟수 공개, 축구와 다른 모델을 같은 잣대로 |
| 6a | [NBA Gold·데이터 신선도](6a_nba_gold_freshness.md) | 여러 종목 Gold, "데이터가 바뀌었나"와 "수집이 돌았나"를 나눈 신선도 검사, Windows가 포트를 예약해 막힌 사건 |

전체 구조는 [코드 가이드](../code_guide.md), 계획과 진행 상태는 [로드맵](../de_platform_roadmap.md), 주제별(예외 처리·메달리온·기술 스택) 정리는 [면접 준비 문서](../interview/README.md)를 함께 보세요.
