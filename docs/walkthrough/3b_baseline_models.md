## 한 줄 요약

세 가지 기준 모델을 "그 주 첫 경기 시작 전에 알려진 결과로만" 매주 다시 학습시키며 지난 시즌들을 예측했습니다. Poisson·Dixon-Coles는 단순 비율보다 확실히 낫지만(로그 손실 1.075 → 0.989), 아직 시장 배당(0.962~0.967)보다 부정확합니다. 그래서 실제 예측 확률은 계속 보여 주지 않습니다(WITHHELD).

## 세 모델

| 모델 | 생각 | 팀을 보는가 |
|---|---|---|
| 단순 비율(`BaseRateModel`) | 지금까지 홈 승·무·원정 승이 몇 %였나. 모든 경기에 같은 확률 | 아니오 |
| Poisson(`PoissonModel`) | 팀마다 공격력·수비력이 있고, 홈 팀은 조금 더 넣는다. 양 팀 득점이 각각 Poisson 분포를 따른다고 보고 점수 확률표(0~10골)를 만든 뒤 승·무·패로 접는다 | 예 |
| Dixon-Coles(`DixonColesModel`) | Poisson은 0:0·1:1 같은 저득점 무승부를 실제보다 적게 본다는 알려진 문제가 있다. 계수 rho로 0·1골 네 점수만 보정 | 예 |

Poisson의 식:

```text
log(홈 기대 득점)   = mu + 홈 이점 + 공격력[홈] − 수비력[원정]
log(원정 기대 득점) = mu          + 공격력[원정] − 수비력[홈]
```

## 설계 결정과 이유

| 결정 | 위치 | 이유 |
|---|---|---|
| numpy만으로 직접 구현(IRLS) | `pipelines/modeling/models.py`의 `PoissonModel.fit` | scipy·scikit-learn 없이도 Poisson 로그 선형 모델은 IRLS(반복 가중 최소제곱) 몇 번으로 학습된다. 식을 직접 구현해 면접에서 계수 하나하나를 설명할 수 있다. 한 번 학습에 수 밀리초 |
| 공격력·수비력에 ridge 벌점 | 같은 함수의 `penalty` | 기록이 적은 팀(승격 팀, 시즌 초)은 0(리그 평균) 쪽으로 당겨진다(축소 추정). 기록이 아예 없는 팀은 정확히 리그 평균으로 예측. 3a에서 "승격 팀은 첫 경기 기록 0"을 확인한 데 대한 대응 |
| 시간 감쇠(반감기) | `PoissonModel.weights` | 팀 전력은 시즌 사이·시즌 중에 바뀐다. 오래된 경기의 가중치를 반감기마다 절반으로 |
| Dixon-Coles는 두 단계 근사 | `DixonColesModel.fit` | 먼저 Poisson과 같은 방식으로 기대 득점을 구하고, 그걸 고정한 채 rho만 격자(−0.25~0.25)에서 고른다. 원 논문처럼 모두 함께 최대화하려면 범용 최적화기가 필요하다. 근사임을 docstring에 남겼다 |
| 확률이 음수가 되는 rho는 버림 | `valid_rho` | 보정한 0:0 확률 등이 음수가 되면 확률이 아니다 |
| 주 단위 재학습 | `pipelines/modeling/backtest.py`의 `blocks`, `walk_forward` | 실제 운영처럼 "매주 새 결과를 받아 다시 학습"을 재현. 같은 주 경기는 그 주 첫 경기 시작 시각(`fit_cutoff`)의 정보로 함께 예측해, 토요일 경기 결과가 일요일 경기 예측에 들어가지 않는다(보수적) |
| 시즌 역할 분리 | `season_roles` | 2021-22는 학습 전용(이전 기록 없음), 2022-23은 **검증**(하이퍼파라미터 선택), 2023-24 이후는 **시험**(고른 설정으로 한 번만 평가). 시험 시즌 성적을 보고 설정을 고르면 성능을 부풀리게 된다 |
| 학습 경기 100개 미만이면 WITHHELD | `MIN_TRAINING_MATCHES` | 근거가 부족하면 확률을 만들지 않는다(저장소 원칙). 사유 코드 `INSUFFICIENT_TRAINING_DATA(<100)` |
| 시장 비교는 같은 경기끼리 | `summarize`의 `vs_market_*` | 시장 배당이 없는 경기가 섞이면 비교가 불공정해진다 |
| 실행·예측 기록 | `pipelines/sql/005_modeling_backtests.sql` | 실행마다 모델 버전(이름·코드 버전·하이퍼파라미터), 데이터셋 해시, 가정을 남기고, 예측마다 학습 기준 시각을 남긴다. 같은 실행을 다시 돌리면 새로 쓰지 않는다(멱등) |
| 누수를 DB가 거부 | 같은 SQL의 CHECK | "학습에 쓴 마지막 경기 + 3시간 ≤ 학습 기준 시각 ≤ 경기 시작", 확률 합 = 1, PREDICTED면 확률 있음·WITHHELD면 사유 있음. 코드에 실수가 있어도 누수된 예측은 저장되지 않는다 |
| numpy를 의존성에 명시 | `requirements.txt` | 지금까지는 Streamlit을 통해 간접 설치됐다. 직접 쓰므로 버전을 고정 |

## 결과를 어떻게 읽나

- **팀 전력을 보는 것만으로 크게 좋아진다.** 단순 비율 1.075 → Poisson 0.990. 강팀과 약팀을 구분하기 때문이다.
- **Dixon-Coles의 이득은 아주 작다(0.001).** 학습 시점마다 rho를 뽑아 보니 −0.105 ~ +0.09로 부호조차 일정하지 않았다(2023-08 0.065, 2024-01 0.09, 2025-01 −0.095, 2025-08 0.01, 2026-10 −0.095). 반감기 180일이면 실질 표본이 한 시즌 남짓이라 0·1골 네 점수로 추정하는 rho가 흔들린다. 검증 시즌에서는 오히려 Poisson이 조금 나았다(0.9850 vs 0.9868). 이 차이가 우연인지는 3c에서 불확실성으로 확인한다.
- **시장보다 0.02~0.03 나쁘다.** 시장 배당에는 부상·라인업·이적 같은 정보가 들어 있고, 이 모델은 점수만 본다. "시장보다 정확하다"는 주장은 할 수 없다.
- **시즌마다 난이도가 다르다.** 2025-26은 시장도 1.01로 어려운 시즌이었다. 시즌 하나만 보고 판단하면 안 된다.
- 홈 이점(기대 득점)은 학습 시점에 따라 +11% ~ +28%였다(2023-08 +28%, 2025-08 +11%, 2026-10 +20%). 시간 감쇠 때문에 최근 한두 시즌의 영향을 크게 받는다.

## 면접에서 나올 만한 질문

**Q. 왜 머신러닝 라이브러리 대신 Poisson을 직접 구현했나요?**
축구 득점 모델의 표준 기준선이 Poisson·Dixon-Coles입니다. 계수(공격력·수비력·홈 이점)가 바로 해석되고, 데이터 2천 경기 수준에서는 복잡한 모델보다 안정적입니다. 식이 단순해서 IRLS로 직접 구현했고, 덕분에 벌점(축소)과 시간 감쇠를 원하는 방식으로 넣을 수 있었습니다. 가상 데이터로 계수를 되찾는 테스트로 구현을 검증했습니다.

**Q. 백테스트에서 미래 정보가 섞이지 않았다는 걸 어떻게 보장하나요?**
세 겹입니다. 첫째, 매주 그 주 첫 경기 시작 시각에 결과가 알려진 경기(시작 + 3시간 ≤ 기준 시각)만 학습에 넣습니다. 둘째, 테스트에서 학습 함수에 넘어간 경기를 전부 기록해 규칙을 확인합니다. 셋째, 예측을 저장할 때 DB CHECK가 "학습에 쓴 마지막 경기 + 3시간 ≤ 기준 시각 ≤ 경기 시작"을 검사해, 어긋나면 저장 자체를 거부합니다.

**Q. 하이퍼파라미터는 어떻게 골랐나요?**
시즌을 학습 전용·검증·시험으로 나눴습니다. 2022-23 한 시즌에서 후보 16개를 비교해 고르고, 그 설정을 고정해 2023-24 이후를 한 번만 평가했습니다. 후보 결과도 모두 DB에 남겨서, 몇 개를 시도해 어떤 걸 골랐는지 숨기지 않습니다.

**Q. 승격 팀처럼 기록이 없는 팀은요?**
공격력·수비력에 ridge 벌점을 걸어 기록이 적을수록 리그 평균으로 당겨지게 했고, 기록이 없으면 정확히 리그 평균으로 예측합니다. 다만 승격 팀은 보통 평균보다 약하므로 이 방식은 승격 팀을 과대평가할 가능성이 있습니다. 3c에서 승격 팀 초반 경기의 오차를 따로 확인할 계획입니다.

**Q. 시장보다 못한데 의미가 있나요?**
기준선의 목적은 "이 정도는 점수만으로 된다"를 정직하게 재는 것입니다. 단순 비율보다 확실히 좋고, 시장과의 차이(0.02~0.03)가 앞으로 넘어야 할 목표입니다. 시장보다 못한 동안에는 확률을 보여 주지 않습니다.

**Q. 같은 백테스트를 다시 돌리면요?**
실행은 모델 버전 × 평가 시즌 × 데이터셋 해시로 식별됩니다. 같으면 새로 저장하지 않고 기존 run_id를 돌려줍니다. 결과가 정정되면 데이터셋 해시가 바뀌어 새 실행으로 남고, 이전 실행도 그대로 보존됩니다.

## 한계

- **과거 재구성 가정 위의 결과입니다.** 결과가 시작 3시간 뒤 알려졌다고 가정했습니다. 실제 운영 성능은 3d의 경기 전 기록(PROSPECTIVE)으로 따로 평가합니다.
- **시장 대비 차이의 불확실성은 아직 계산하지 않았습니다.** Poisson과 Dixon-Coles의 0.001 차이가 의미 있는지도 모릅니다(3c: 블록 부트스트랩).
- **확률 보정(calibration)도 아직 확인하지 않았습니다.** 예: "60%라고 한 경기들이 실제로 60% 이겼나"(3c).
