## 한 줄 요약

EPL만 다루던 수집·변환·검증을 다섯 리그로 넓혔습니다. 과거 7시즌(2020-21~2026-27) 9,604경기를 더 수집했고, 실시간 수집기가 다섯 대회를 한 번에 돕니다. 새 리그 팀 대조표 76개는 같은 날짜 경기 근거로 검토했습니다. 모델은 아직 EPL로만 학습·평가했기 때문에, 다른 리그 경기의 경기 전 예측은 확률 없이 `LEAGUE_NOT_MODELED`로 보류합니다.

## 소스 확인(2026-10-21)

| 리그 | openfootball(공개 도메인) | football-data.org 무료 | The Odds API |
|---|---|---|---|
| EPL | `en.1`, 2020-21~2026-27 모두 있음 | `PL` | `soccer_epl` |

| 라리가 | `es.1`, 모두 있음 | `PD` | `soccer_spain_la_liga` |
| 세리에A | `it.1`, 모두 있음 | `SA` | `soccer_italy_serie_a` |
| 에레디비시 | `nl.1`, 모두 있음 | `DED` | `soccer_netherlands_eredivisie` |

The Odds API 키는 크레딧이 들지 않는 리그 목록 조회로 확인했습니다: 정상, 크레딧 500/500 남음, 다섯 리그와 NBA 모두 활성.

## 바꾼 것

| 변경 | 위치 | 이유 |
|---|---|---|
| 리그 목록을 한곳에 | `pipelines/leagues.py` | 소스마다 리그 이름이 다르다(openfootball `de.1`, football-data.org `BL1`, The Odds API `soccer_germany_bundesliga`, co.uk `D1`). 한곳에서 대응시키면 리그를 늘릴 때 고칠 곳이 하나다 |
| 에레디비시 시간대 | `openfootball.LEAGUE_TIMEZONES["nl.1"]` | 현지 시각을 UTC로 바꾸는 데 필요 |
| 수집기가 다섯 대회를 차례로 | `football_data_org.run_forever` | 대회별 다음 조회 시각을 따로 둔다. 경기 중인 리그만 2분마다, 나머지는 각자의 간격. 분당 10회 한도는 RateLimiter 하나가 함께 지킨다. 한 리그 조회가 실패해도 나머지는 계속 |
| 팀 대조표 76개 | `pipelines/mappings/team_aliases.csv` | football-data.org 팀 ID → openfootball 이름. 2026-27 같은 날짜(±1일) 경기 근거가 모두 90% 이상, 같은 이름에 두 ID가 겹치지 않음, 이름도 76개 모두 같음 |
| 매일 DAG가 (리그, 시즌) 10개를 | `dags/openfootball_epl_daily.py` | 동적 작업. GitHub 요청이 몰리지 않게 동시에 2개까지. 실행 기록을 잇기 위해 DAG 이름은 그대로 둠 |
| 모델은 EPL로만 | `leagues.MODELED`, `Predictor`, `load_dataset(competitions=…)` | 다른 리그로 학습·평가한 모델이 없다. EPL 모델로 다른 리그를 예측하면 그럴듯하지만 근거 없는 확률이 된다. 경기 전 예측은 `LEAGUE_NOT_MODELED`, 학습 자료는 EPL만 |
| 텔레그램 사유 문구 | `alerts.REASON_LABEL` | "이 리그 모델 없음" |

중요한 순서: 대조표가 없는 상태로 수집기를 켜면 새 리그 이벤트가 모두 거부됩니다. 그래서 openfootball 수집(팀 생성) → 대조표 검토·추가 → 소비자 재시작(대조표 반영) → 수집기 재시작 순서로 했습니다. 경기 전 예측 코드도 Airflow가 실시간으로 읽기 때문에, 다른 리그 경기가 스냅샷에 잡히기 전에 EPL 한정을 먼저 넣었습니다.

## 면접에서 나올 만한 질문

**Q. 리그를 늘릴 때 무엇이 가장 위험했나요?**
두 가지입니다. 첫째, 팀 대조표 없이 실시간 수집기를 켜면 새 리그 이벤트가 모두 거부되므로 순서를 정해 진행했습니다. 둘째, EPL로만 학습한 모델이 다른 리그 경기에도 그럴듯한 확률을 내는 것입니다. 경기 전 예측 코드가 실시간으로 반영되는 구조라, 다른 리그 경기가 스냅샷에 잡히기 전에 "학습·평가한 리그만 예측" 규칙을 먼저 넣었습니다.

**Q. 새 리그 데이터가 맞는지 어떻게 확인했나요?**
자동 검사(dbt 순위표 정합성, 시점 누수 재계산, Spark 대조)에 더해, 널리 알려진 사실과 대조했습니다. 다섯 리그 2023-24 우승팀과 승점이 모두 공개 기록과 같았습니다(예: 레버쿠젠 무패 90점).

**Q. 팀 이름을 소스끼리 어떻게 맞췄나요?**
이름을 추측하지 않고, football-data.org 팀 ID별로 같은 날짜(±1일)에 열린 openfootball 경기를 세어 가장 많이 겹치는 팀을 후보로 삼았습니다. 76개 모두 근거가 90% 이상이고 겹침이 없을 때만 대조표에 넣었습니다.

## 한계

- **모델은 EPL만 있습니다.** 다른 리그 예측은 보류입니다(5c).
- **경기 기록(슈팅·퇴장)도 EPL만 있습니다.**
- **텔레그램 경기 전 알림이 늘어납니다.** 다섯 리그의 스냅샷이 모두 알림에 들어갑니다.
- **DAG 이름에 "epl"이 남아 있습니다.** 실행 기록을 잇기 위해서입니다.
