| 항목 | 내용 |
|---|---|
| 허용 | 상업적 이용 포함(데이터 자체를 주된 상품으로 팔지 않는 한), 파생값 계산, 연구, 통계·머신러닝 모델 학습 |
| 보관 | 기한 없음 |

| 금지 | 재판매·재배포(원자료를 남에게 제공) |
| 키 | 비공개 유지(새면 크레딧이 소모됨). `.env`의 `THE_ODDS_API_KEY`에만 |
| 무료 등급 | 월 500크레딧. `/odds`는 시장 수 × 지역 수(우리는 1X2 1 × 유럽 1 = 1크레딧, 그 리그 경기 전체), `/events`·`/sports`는 무료 |

검토 결과는 `ingest.sources`(`011_the_odds_api.sql`)에 자동 수집 허용과 함께 남겼습니다.

## 흐름

```text
prematch_snapshots DAG(30분마다)
 ├ fetch_due_odds   리그별 /events(무료) → 24시간·1시간 전 스냅샷이 35분 안에 오면 /odds(1크레딧)
 │                  → Bronze(원본 JSON) → silver.odds_revisions(source = the-odds-api, 값이 바뀐 것만 새 버전)
```

## 설계 결정과 이유

| 결정 | 위치 | 이유 |
|---|---|---|
| 24시간·1시간 전에만 받음 | `pipelines/ingest/the_odds_api.py`의 `due_offsets` | 다섯 리그 × 경기 시각 묶음 × 3번이면 월 500크레딧을 넘는다(추정 약 450). 2번이면 약 300. 3시간 전 스냅샷은 24시간 전 배당을 쓴다 |
| 같은 리그는 한 번에 | `/odds` 한 번 = 리그의 다가올 경기 전체 | 같은 시각에 시작하는 경기들을 따로 받지 않는다 |
| 90분 안에 받았으면 다시 안 받음 | `REFETCH_AFTER` | 겹치는 경기 시각 때문에 연달아 받는 것을 막는다 |
| 크레딧이 60 아래면 1시간 전만 | `RESERVE_CREDITS` | 남은 크레딧은 응답 헤더 `x-requests-remaining`으로 본다 |
| 배당 발표 시각 = 북메이커 `last_update` | `quotes`, `published_at` | 이 배당이 언제 그 값이 됐는지 안다. 기준 시각 함수가 그 시각과 받은 시각을 모두 본다 |
| 팀 이름은 검토한 대조표로만 | `mappings/team_aliases.csv`(source = the-odds-api, 96개) | 같은 리그에서 시작 시각이 정확히 같은 경기 중 이름이 가장 비슷한 경기로 후보를 만들고, 유사도 0.75 미만 16개는 사람이 확인했다(AZ Alkmaar ↔ AZ, Inter Milan ↔ FC Internazionale Milano 등) |
| 연결 실패는 품질 문제로 | `silver.quality_issues`(`UNMAPPED_TEAM`, `MATCH_NOT_FOUND`) | 버리지 않고 남긴다 |
| 배당 수집 실패가 스냅샷을 막지 않음 | DAG `trigger_rule="all_done"`, 재시도 0 | 스냅샷은 그때 알려진 배당으로 찍는다. 재시도로 크레딧을 쓰지 않는다 |
| 키를 오류에서 지움 | `call`(`raise … from None`) | 키가 URL 쿼리에 들어간다 |
| Kafka를 거치지 않음 | 수집기가 Silver에 바로 | 하루 몇 번 받는 배치라 실시간 스트림이 필요 없다(co.uk 수집과 같은 방식) |

## 면접에서 나올 만한 질문

**Q. 무료 API 한도 안에서 어떻게 운영하나요?**
일정 조회는 무료라 그것으로 경기 시각을 보고, 실제로 예측을 기록하는 시점(24시간·1시간 전) 바로 전에만 배당을 받습니다. 같은 리그 경기는 한 번에 받고, 90분 안에 받았으면 다시 받지 않고, 응답 헤더로 남은 크레딧을 보면서 모자라면 1시간 전만 받습니다. 그렇게 해서 다섯 리그를 월 약 300크레딧으로 잡았습니다.

**Q. 배당이 "언제의 값"인지 어떻게 아나요?**
북메이커별 시장의 `last_update`를 발표 시각(published_at)으로, 받은 시각을 received_at으로 저장합니다. 기준 시각 함수가 둘 다 기준 시각 이전인 버전만 고르므로, 스냅샷은 그때 알려진 배당만 봅니다.

**Q. 해외 기준 확률은 왜 Pinnacle인가요?**
마진이 작고 큰 금액을 받아 줘서 배당이 정확하다고 알려진 북메이커라서, 공정 확률의 추정치로 흔히 씁니다. 없으면 3곳 이상의 평균을 쓰고, 어느 것을 썼는지 기록에 남깁니다.

## 한계

- **3시간 전 스냅샷의 해외 배당은 21시간 전 값입니다**(크레딧 절약).
- **크레딧 사용량은 추정입니다.** 실제 사용량은 실행 기록의 `credits_remaining`으로 봐야 합니다.
- **과거 배당이 아닙니다.** The Odds API의 과거 배당은 유료라, 다른 리그의 과거 시장 비교(백테스트)에는 쓸 수 없습니다.
