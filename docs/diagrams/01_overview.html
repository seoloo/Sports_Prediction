01 WHY

왜 시작했나

🎯 바로 채점할 수 있는 시험대

스포츠는 결과가 며칠 안에 나와 경기 전 예측을 곧바로 채점할 수 있고, 시장 배당이라는 강한 기준선이 있습니다. 그런데 "이 숫자를 믿어도 되나"를 확인하려 하자 모델보다 데이터가 먼저 문제였습니다.

문제 1미래 정보가 섞인다

경기 후 정정된 기록이나 마감 직전 배당이 학습에 섞이면 백테스트가 실제보다 좋아 보입니다.

문제 2데이터는 계속 바뀐다

일정 변경·결과 정정·배당 변동이 흔합니다. 덮어쓰면 "그때 무엇을 알았는지" 재현할 수 없습니다.

문제 3소스마다 이름·시각·조건이 다르다

팀 이름 표기, 시작 시각 10분 차이, 소스의 점수 오류, 약관마다 다른 저장·재배포 범위, 무료 API 월 500회 한도.

그래서 모든 자료에 발표 시각과 수신 시각을 남기고, 덮어쓰지 않고 버전으로 쌓아, 어느 시점이든 그때의 입력을 재현합니다. 검증을 못 넘은 확률은 보여 주지 않습니다.

02 HOW

문제마다 고른 기술

SeaweedFS (S3)Bronze · 원본
받은 원본을 내용 해시 경로로 바이트 그대로 보존 → 언제든 다시 처리. 표준 S3 API(boto3)
PostgreSQLSilver · 버전
버전 테이블 + 트리거로 수정·삭제를 DB가 차단, *_known_at(as_of) 함수로 그때의 데이터를 조회
Kafka스트리밍
경기 갱신은 원래 시간순 이벤트. JSON Schema 계약으로 깨진 메시지는 오류 큐로, 중복·늦은 도착을 거르고 과거 시즌을 재생해 검증
dbtGold · 품질 테스트
순위표·시점 특징·배당 확률을 코드로 정의, 품질 테스트 38개, 과거 기준 시각으로 재계산
Spark · Iceberg레이크 · 대조
Gold를 Iceberg 테이블 스냅샷으로 쌓아 그날의 Gold를 시간 여행으로 읽고, Spark로 독립 재계산해 dbt와 행 단위 대조(불일치 0)
Airflow오케스트레이션
매일 수집·변환, 30분마다 경기 전 스냅샷, 주간 채점, 실패 알림. API 크레딧 예산 안에서
numpy모델 · 평가
Poisson·Dixon-Coles·점수 차 등급·Elo, 시간순 백테스트 + 블록 부트스트랩 검증 기준
Docker · CI재현 · 검증
Compose로 전체 스택 재현, GitHub Actions에서 테스트 216개 + Spark + dbt
